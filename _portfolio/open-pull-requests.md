Beyond the merged work above, I have open pull requests across the rest of the AI infrastructure stack. Each link goes to the upstream discussion; several carry a minimal reproducer, a measurement, and a regression test.

- **PyTorch** — [#196787: fix NaN in higher-order gradients of `logaddexp` / `logaddexp2`](https://github.com/pytorch/pytorch/pull/196787). The backward weight was written as `1 / (1 + exp(other - self))`, which overflows to `inf` once the difference exceeds `log(DBL_MAX)`, so the expression autograd differentiates for a double backward evaluates to `inf / inf = nan` for finite inputs. The formula now uses `sigmoid`, which is bounded. Fixes [#196704](https://github.com/pytorch/pytorch/issues/196704).
- **vLLM** — [#56198: reject `int4_per_token_head` for non-power-of-two head sizes](https://github.com/vllm-project/vllm/pull/56198). The mode's write path asserts a power-of-two dimension, but the option was accepted for every head size, so a model with head size 96 selected TRITON_ATTN and then aborted inside the engine-core process with an opaque message. Fixes [#56197](https://github.com/vllm-project/vllm/issues/56197).
- **SGLang** — [#39315: throttle the fully-idle load snapshot publish](https://github.com/sgl-project/sglang/pull/39315). With `--sleep-on-idle` off, an idle scheduler republished an unchanged load snapshot on every pass: 10,470 publishes/s and ~0.36 CPU cores on a single-H200 server, measured before and after.
- **Megatron-LM** — [#7287: describe prepended-axis shards with the checkpointable path](https://github.com/NVIDIA/Megatron-LM/pull/7287). The legacy PyTorch conversion enumerates the entire global shard grid — remote shards included — for every key with a prepended axis, so its cost scaled with total fragmentations rather than locally held shards. Closes [#7275](https://github.com/NVIDIA/Megatron-LM/issues/7275).
- **TensorRT-LLM** — [#18904: make `BlockRadixTree.clear()` terminate on a childless root](https://github.com/NVIDIA/TensorRT-LLM/pull/18904). `clear()` shrank its queue only as a side effect of detaching a child, so a `RootBlock` that was already childless made the outer loop re-select the same root forever. Closes [#17908](https://github.com/NVIDIA/TensorRT-LLM/issues/17908).
- **CUTLASS** — [#3613: skip cuBLAS verification when C and D element types differ](https://github.com/NVIDIA/cutlass/pull/3613). `cutlass_profiler` aborted the entire profiling session with SIGABRT when it reached an SM90 GEMM writing narrow FP8 output from an FP32 `C`, which kills a full kernel sweep at the first such kernel.
- **LMCache** — [#5117: reject non-positive sizes in `AddressManager`](https://github.com/LMCache/LMCache/pull/5117), where a zero-byte request corrupted the explicit free list — inserting an uncoalescable zero-sized entry while `get_free_size()` kept reporting the heap as free — and `batched_allocate(0, n)` raised `ZeroDivisionError`; and [#5125: enforce lazy `%`-format logging (ruff G004)](https://github.com/LMCache/LMCache/pull/5125), which stops new f-string logging from landing in already-migrated files and ends the stream of one-file migration pull requests.
- **Miles (ROCm / FSDP)** — [#3266](https://github.com/radixark/miles/pull/3266) non-scalar rewards aborting the on-policy-distillation rollout in the zero-std metrics, [#3267](https://github.com/radixark/miles/pull/3267) resolving the SGLang Triton attention kernel across layouts after its module relocation, [#3268](https://github.com/radixark/miles/pull/3268) applying the Qwen3 precision contract in the AMD true-on-policy example (measured on MI300X / gfx942), and [#3269](https://github.com/radixark/miles/pull/3269) a verify step that spoke only CUDA while the hardware table listed AMD.
- **Cordis** — [#148: apply updates issued while a fiber is loading](https://github.com/cordiverse/cordis/pull/148). A restart issued during load toggled the dependency epoch through INACTIVE and back, so the in-flight reload cleared inertia without applying the new configuration; a generation counter fixes the lost update. Fixes [#34](https://github.com/cordiverse/cordis/issues/34).
