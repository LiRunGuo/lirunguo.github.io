Every key gets a random perturbation, a threshold descends level by level, and the head stops reading keys the moment its error bound meets the target. Below, the paper's value-scale certificate runs live on synthetic attention heads with 32,768 keys.

The head keeps reading until the blue bar ends left of the target line. The diamond is the error actually made, which the algorithm cannot see; the gap to the bar is the price of a guarantee that holds at every level at once.

Same target, three ways to spend keys on 200 heads. The certificate picks a level per head. One fixed level uses the same estimator at a single level for every head, matched to our mean keys read. Oracle top-k reads exactly our number of keys on each head but keeps only the highest true scores.
Target ε

Heads range from diffuse to sharply peaked, with one call each and fresh perturbations. A fixed level's sample grows with a head's total weight, so it reads too few keys on peaked heads (left, large errors) and too many on flat ones (right, errors far below ε). Oracle top-k drops the attention mass of the keys it does not read, so its error is a bias, not noise.

Synthetic heads; the numbers are not the paper's measurements. The certificate is the paper's value-scale rule with exact scores (δ = 0.05, r = 4 levels per octave, J = 160), ported from the reference implementation that tests the paper's kernel and matching it exactly. The kernel's 4-bit candidate scan is omitted: it returns the same sample.
